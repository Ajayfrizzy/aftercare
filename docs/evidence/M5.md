### Private-only wake feasibility decision

Decision: hold deployment. Fly documents org-only URL authentication, org API tokens managed through sprites.dev/account, and service wake on incoming HTTP. The available CLI identifies its credential as an organization token used for both SDK and API access. A private URL and a Worker secret do not limit what a stolen token authorizes. No evidence reviewed establishes an independently revocable ingress-only grant confined to one Sprite, one POST path, without exec, file, proxy or management access. Fly MCP consent scopes govern MCP clients; they do not establish equivalent URL ingress scopes.

Cloudflare Free supports the scheduled-only handler and encrypted bindings. A possible protocol, conditional on Fly confirmation, is separate edge Authorization and X-Aftercare-Wake authentication. Neither forwarding nor stripping of Authorization should be assumed. Require provider documentation on which credential and headers private ingress accepts, which headers reach the application, and enforcement of scope, expiry and revocation. Cold wake may take longer than warm resume; an HTTP timeout can leave the delivery outcome unknown. No method-specific guarantee or maximum latency for authenticated empty POST was verified. Do not forward an org administration credential. Keep catch-up-on-wake active.

Only after written scope confirmation and fresh owner approval: test on a disposable private Sprite, verify both denied credentials independently and an unrelated route, then schedule one fixed-origin HTTPS POST after observed cold, reconcile worker and SQLite timestamps, replay after restart, revoke and verify denial. Keep all logs credential-free, redirect refusal and bounded execution. No provisioning, minting or wake request in this investigation.
